## 版本范围

本页说明从 4.x 迁移到正式版 **5.0.0**。安装 `hapin-utils@5.0.0`，与本文 API 及 `context-v1` 规则保持一致。已有转换函数继续保留，来源转换的错误修复可能改变过去不正确的结果。

## 保持历史行为或采用上下文规则

已有 transform 函数继续提供。`transformHapinToArabic('ngh')` 保留历史结果 `ڭح`；新 `convert('ngh', { from: 'hapin', to: 'arabic' })` 首选 `نع`，并报告竞争切分。新 API 可指定 rules: legacy 保留历史字母优先级，但布局仍默认 preserve，除非另行指定。

两类 API 的来源转换都修正为：нғ→نع、ңх→ڭح、нг→نگ，不再经由隐式中间 Hapin 字符串。引号可以安全结束，未知 y 不再消失；弱音符号与 IPA 的词级修复可能改变过去错误的结果。

## 旧边界数据

导入旧 U+200B 分隔 Hapin 时指定 inputFormat: legacy-boundaries。新 plain 输入保留原始零宽字符，不把它们当作机器协议。只有兼容包装函数继续用 clean=false 输出旧边界；旧 easy 单引号属于展示文本，不是已支持的输入分隔符。

## 布局、数组与有损映射

新 API 默认保留布局；兼容包装保留历史布局约定，但不再改写受保护的引号原文。结构化字母使用 analysis units，三个旧 Array 函数继续拆分历史序列化形式。

不能要求简洁显示编码往返后与来源字串完全一致。需要源字形时保留原分析并检查 losses；严格模式拒绝未决输入，不返回伪成功的部分转换文本。
