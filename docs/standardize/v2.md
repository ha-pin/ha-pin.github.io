## Scheme and implementation versions

The scheme version is separate from the npm package version and the segmentation rule version. This documentation targets **hapin-utils 5.0.0** with the `context-v1` segmentation rules.

## Letter boundaries

Earlier 4.x code used U+200B ZERO WIDTH SPACE as an invisible machine boundary. This was a serialization convention, not a watermark or a linguistic letter. Cleaning an intermediate Hapin string could erase the distinction between N,GH and NG,H.

The new implementation passes structured letter units between parsers and renderers. Normal output does not generate hidden boundaries. Existing zero-width characters in plain input are preserved; explicit `inputFormat: 'legacy-boundaries'` imports old machine-separated Hapin. Existing wrappers retain `clean=false` serialization.

## Contextual segmentation

The old double-letter greedy parser is available as `legacy`. The 5.0.0 API ranks alternative letter analyses using source-attested forms and contextual evidence. See [Segmentation rules](/standardize/segmentation) and [Evidence and limitations](/standardize/segmentation-evidence).

The earlier apostrophe proposal (`g'h`) was **not implemented as an input delimiter**. Do not use it as supported syntax. Apostrophes in old `easy` output are a display convention. To retain an explicit distinction, pass structured units or import legacy boundaries.

## Compatibility

Existing transform functions keep their signatures and legacy Hapin parsing. Source-boundary, quote, front-vowel and word-scope bugs are fixed. See [Migration](/developer/hapin-utils-migration). Reference tables describe scheme intent; they do not guarantee reversible conversion or support for every historical alias.
